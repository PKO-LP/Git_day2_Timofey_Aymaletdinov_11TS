# Что такое git?

<img width="200" height="200" alt="git" src="https://github.com/user-attachments/assets/539542f1-a479-443a-9f39-40ba6971e1c0" />

**Git — это система контроля версий. Проще говоря, это инструмент, который помогает хранить историю изменений файлов (чаще всего кода) и управлять ими.**

# Для чего нужен git?

## Git нужен, чтобы:

**Отслеживать изменения в файлах. Он фиксирует каждую правку и сохраняет историю: что, когда и кем было изменено.
Возвращаться к прошлым версиям. Если после новых правок что-то сломалось, можно быстро откатиться к рабочему состоянию.
Работать в команде без путаницы. Несколько человек могут менять разные части проекта одновременно, а Git поможет аккуратно объединить эти изменения.
Экспериментировать безопасно. Можно создавать отдельные ветки для новых идей — они не испортят основную версию проекта, пока не будут готовы.
Хранить резервные копии. Проект можно держать и на компьютере, и на удалённом сервере (например, GitHub или GitLab) — так данные не пропадут, если что-то случится с одним из устройств.**

# За что отвечает команда git init?

**Эта команда создаёт новый Git‑репозиторий в текущей папке.
Простыми словами: ты говоришь проекту «теперь ты под контролем Git». После неё в папке появляется скрытая директория .git — в ней Git хранит всю историю изменений, настройки и прочее.**

# За что отвечает команда git add?

**Команда добавляет изменения в индекс (его ещё называют «staging area» — зона подготовки).
Это как положить файлы в корзину перед покупкой: ты отмечаешь, какие именно правки хочешь сохранить в следующем коммите. Например:**

**git add file.txt — добавить один файл;
git add . — добавить все изменения в текущей папке.
Без git add команда git commit не увидит твоих правок.**

# За что отвечает команда git commit?

**Команда фиксирует подготовленные изменения как отдельный «снимок» проекта — коммит.
Это уже не просто подготовка, а настоящее сохранение: Git запоминает состояние файлов, автора, дату и твоё сообщение о том, что сделано. Обычно используют с комментарием:
git commit -m "Добавили главную страницу".**

# Зачем необходимо комментировать коммиты?


## Зачем комментировать коммиты
**Комментарий нужен, чтобы понять, что именно изменилось и зачем, даже спустя месяцы или годы.**

## Зачем это на практике:

**Быстро найти нужное изменение. Если вдруг что‑то сломалось, можно просмотреть историю (git log) и быстро найти коммит, который всё испортил.
Объяснить логику другим (и себе). Комментарий вроде «Исправили баг с формой входа: теперь не падает при пустом email» сразу даёт контекст, а не просто «обновили форму».
Упростить код‑ревью. Коллеги быстрее поймут смысл правок и смогут дать полезные замечания.
Восстановить картину при откатах. Если придётся вернуться к старой версии, комментарии помогут выбрать правильный момент в истории.**
